# Словарь данных и измерений

CSV кодируется в UTF-8, разделитель `,`, первая строка содержит имена столбцов. Текст с запятой или переводом строки заключают в двойные кавычки; внутреннюю кавычку удваивают. Временные метки используют `YYYY-MM-DDTHH:MM:SS+HH:MM`. Храните идентификаторы как текст. Пустое поле означает «не записано / ещё не применимо», а не ноль.

Данные команды являются недоверенным вводом. При импорте задавайте текстовый тип для полей вопроса и действия; не позволяйте значениям с `=`, `+`, `-` или `@` исполняться как формулы. Перед экспортом просмотрите поля в редакторе как обычный текст. Не переносите реальные строки в публичный репозиторий.

## Очередь

| Столбец | Правило |
|---|---|
| `ticket_id` | Уникальный номер, например `Q-001`; не переиспользовать в одном событии |
| `team_code` | Внутренний код команды; связь с участниками хранится отдельно |
| `received_at` | Первое получение обращения, неизменно |
| `acknowledged_at` | Первое подтверждение команде с номером |
| `queue_round` | `1` для первой очереди; увеличивается только при новом запросе помощи после сессии или проверки команды |
| `queued_at` | Готовность вопроса в текущем раунде; основной ключ сортировки |
| `status` | Одно состояние из списка ниже |
| `topic` | Одна тема из согласованного списка; например `tech`, `product`, `pitch`, `operations` |
| `language` | Согласованный язык общения, например `ru`, `kk`, `en` |
| `question` | Короткий безопасный вопрос без секретов и персональных данных |
| `mentor_id` | Код назначенного ментора; до назначения пусто |
| `owner_role` | `dispatcher` или `mentor`; роль владельца записи |
| `owner_code` | Один код текущего ответственного; обязательно во всех открытых состояниях |
| `due_at` | Срок следующего действия владельца; обязательно во всех открытых состояниях |
| `next_action` | Конкретный следующий шаг; обязательно во всех открытых состояниях |
| `assigned_at` | Назначение ментора в текущем раунде; историю прежних назначений сохраняет журнал |
| `started_at` | Начало текущей / последней сессии; при новом раунде обнуляется после переноса старого времени в журнал |
| `ended_at` | Конец текущей / последней сессии; при новом раунде переносится в журнал |
| `closure_reason` | `answered`, `action_agreed`, `unavailable`, `withdrawn`, `duplicate`; для открытых пусто |
| `closed_at` | Время завершения; для открытых пусто |
| `handover_to` | Предложенный код нового владельца; сам по себе не передаёт ответственность |
| `handover_accepted_at` | Явное подтверждение передачи; после принятия новый код становится `owner_code` |
| `private_ref` | Внутренний код закрытой заметки; не публичный URL и не контакт |
| `updated_at` | Последнее изменение строки диспетчером |

После назначения без подтверждения `owner_role=dispatcher`. После принятия ментора `owner_role=mentor`. При передаче код прежнего владельца сохраняется до `handover_accepted_at`.

## Состояния

| Значение | Значение для работы |
|---|---|
| `received` | Обращение зарегистрировано, требуется подтверждение или уточнение |
| `needs_info` | Не хватает контекста или подтверждённой готовности команды |
| `needs_route` | Нет подтверждённого подходящего пути помощи; диспетчер ищет вариант |
| `queued` | Вопрос готов и ждёт доступного подходящего ментора |
| `assigned` | Выбран ментор, ожидается его подтверждение или начало встречи |
| `in_session` | Идёт консультация |
| `awaiting_handover` | Передача предложена, прежний владелец ещё отвечает |
| `team_action` | Команда проводит согласованную проверку, диспетчер ждёт следующего контакта |
| `closed` | Есть явный итог, время и причина закрытия |
| `cancelled` | Команда отозвала запрос или исправлена ошибочная запись; причина `withdrawn` |
| `duplicate` | Дополнительная запись объединена с основной; причина `duplicate` и основной номер в журнале |

Последние три состояния являются завершёнными. Для остальных `owner_code`, `due_at`, `next_action` не могут быть пустыми. При повторном открытии закрытой строки используйте новый номер со ссылкой на прежний в журнале; старую запись не перезаписывайте.

## Остальные CSV

- `mentor-roster.csv`: `mentor_id`, `topics`, `languages`, `available_from`, `available_until`, `confirmed_at`, `location_code`, `status`, `coordinator_code`. Несколько тем / языков разделяют `|`. Состояние `confirmed`, `unconfirmed` или `unavailable`. Место является внутренним кодом, а не публичной ссылкой.
- `queue-decisions.csv`: `decision_id`, `ticket_id`, `recorded_at`, `actor_code`, `from_status`, `to_status`, `reason_code`, `decision`, `owner_after`, `due_after`. Одна строка на важный переход, назначение, перенос срока или исключение. Для перехода нового раунда в `decision` укажите номер раунда и его `queued_at`; для начала и конца сессии укажите фактические времена. Журнал хранится в том же закрытом доступе, что и очередь.
- `public-status.csv`: `ticket_id`, `display_status`, `next_update_at`, `notice`. Только обезличенное состояние и организационная инструкция. Не добавляйте команды, менторов, вопросы, комнату и причины специальных условий. Публикуйте внутри каналов события, а не в GitHub.
- `closeout-metrics.csv`: `metric_id`, `definition`, `target`, `numerator`, `denominator`, `value`, `unit`, `window_start`, `window_end`, `source`, `missing_values`, `notes`. В `source` укажите приватный код выгрузки / журнала; итог для внешнего отчёта содержит только агрегаты.

## Как считать результат

| Метрика | Определение и границы |
|---|---|
| Полнота открытых строк | Строки с владельцем + сроком + действием / все открытые строки на момент проверки; при отсутствии открытых строк пишите «не применимо» |
| Подтверждение в целевое время | Запросы, подтверждённые не позднее локального ориентира от `received_at`, / все самостоятельные запросы, полученные в окне; неподтверждённые входят в знаменатель и отмечаются отдельно |
| Первое ожидание | Для каждого запроса: первое `started_at` минус `queued_at` первого раунда из журнала. Запросы, не дошедшие до встречи, не имеют этой длительности и показываются отдельным числом |
| Длительность сессии | `ended_at` минус `started_at` для каждой сессии из журнала; отсутствующие значения перечисляются отдельно |
| Передачи с подтверждением | Принятые новым владельцем передачи / все начатые передачи в окне; ожидающие и отклонённые показываются отдельно |
| Необъяснённые пропуски порядка | Число назначений, где более ранний совместимый и готовый запрос пропущен без причины в журнале; вычисляется по снимкам очереди и решениям |
| Отсутствие компетенции | Число самостоятельных запросов, попавших в `needs_route` из-за отсутствия специалиста / все самостоятельные запросы в окне; каждый запрос считается один раз |
| Закрытие с исходом | Завершённые самостоятельные запросы с `closed_at` и допустимой причиной / все завершённые самостоятельные запросы в окне |

Самостоятельный запрос исключает строки `duplicate`. Отозванные запросы считаются отдельно и не улучшают метрику помощи. Для каждого отчёта фиксируйте окно, число запросов и пропущенных измерений. При малом числе наблюдений показывайте отдельные длительности; если считаете p90, договоритесь о методе и укажите его. Нельзя сравнивать ожидание только обслуженных запросов, скрывая оставшихся в очереди.
